# Windows 手势 UI/UX 复核 — 2026-09-19

## 目标与方法

让用户直接找到启动入口、看懂手指如何摆放、区分识别与真实执行结果。按 Product Design 的流程审查与 Impeccable 的布局原则进行现有界面改进，不更换产品视觉身份。

两项独立评估：layout_review 负责界面/阅读顺序；layout_scan 负责机械扫描/容器风险。机械初查和改后扫描均为 0 条；人工与渲染检查仍发现真实问题，因此不把扫描通过当作 UX 通过。

## 发现与处理

1. 主入口隐藏在标题栏手形图标中，坐姿和 Codex 任务抢占主层级。Windows 模式现在先呈现有文字的启动/暂停与完整手册，镜头和设备作为辅助区域。
2. 六手势的动作名在小格内截断，图标仍沿用 Codex 语义。现在使用 Windows 动作图标、完整动作名、具体手指说明与不同动作的实际效果。
3. Windows 食指动作是任务视图，但旧页面仍提示激活 Codex 话筒。现在只有 Codex 模式保留该提示，语音命令与麦克风输入电平分开说明。
4. 候选识别不等于成功执行。手册只显示“正在识别”，真实回调结果单列“执行结果/未执行”；暂停、摄像头关闭和模型状态分别显示。
5. 用户明确坐姿只是可选功能。摄像头会话默认不加载 PoseLandmarker、不校准身体；仅主动开启坐姿功能才启用。切换到其他工具或手势模式时停止坐姿推理。
6. 窄屏渲染曾出现两列改一列后行高被压缩、内容重叠；改用内容高度的行轨道，实测 390 px 页面宽度无横向溢出，镜头区位于手册区之后。

## 后续验收边界

发布检查补充：Windows runner 的 1024×720 工作区会将镜头压到原先 230 px 下限，未达到既有原生可用性检查（高度 >240 px）。将镜头下限提高至 260 px，并添加相同尺寸的自动回归用例；不放宽原生检查门槛。

真人手势稳定性、误触发率、不同光照与手部遮挡需实机验收。网页预览明确不能执行 Windows 原生窗口操作。
