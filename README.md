# Codex Gesture Dock

一个隐私优先的 Windows Codex 控制系统。它通过本地摄像头手势、Codex App Server 和安全快捷键桥控制核心 Codex 工作流；“端正”坐姿监测是同一悬浮 Dock 中的辅助模块。平时显示桌面角落的迷你摄像头 Dock，点击后展开完整控制面板。MediaPipe 全程在本机分析画面，不录制或上传视频；麦克风只在用户明确开启时读取本机输入电平。

本工作区由 Codex 任务“探索摄像头开源方案”迁移而来。原对话中的需求、决策、版本演进和验证结论见 [迁移档案](docs/imported-chat-exploration.md)，最初调研的开源项目见 [电脑摄像头开源方案地图](docs/open-source-camera-landscape.md)。当前源码版本为 0.5.0，正式构建从 [GitHub Releases](https://github.com/silverlion2/codex-gesture-dock/releases) 下载。

这是一个非官方社区项目，与 OpenAI 没有隶属或背书关系。Codex 是其各自权利人的商标。

## Codex 控制系统

- `348 × 360` 无边框置顶迷你摄像头 Dock，可拖动位置；摄像头运行时控制条在移入鼠标或键盘聚焦后出现
- 点击展开默认 `1120 × 760` 双栏监测台；展开窗口可安全调整大小，迷你与展开位置/尺寸分别记忆
- 可在 Codex / Windows 两套独立手势模式间切换；Windows 模式提供显示桌面、任务视图、资源管理器和音量控制
- 摄像头、实时识别状态和完整 6 项手势手册在主面板中始终可见
- 文件与任务操作使用更宽的独立窗口；优先列出刚完成但尚未查看的文件，也可切换最近、已完成和已归档任务，不遮挡实时画面
- 任务可打开、继续处理、只读总结、审查、测试修复或归档，执行前二次确认
- 活跃任务使用 `turn/steer` 安全追加指令，避免与正在运行的回合冲突
- 自动连接 Codex Desktop 最新版本化 App Server 运行时，绑定当前工作区任务并同步线程、回合和文件事件
- 主面板分别显示 Codex Adapter、Windows Control Core、只读 UI Automation、实时窗口事件和当前绑定任务的状态
- Codex 请求执行命令或修改文件时，Dock 会自动展开并显示逐次审批；只提供“仅允许本次”和“拒绝”
- 快捷键发送前验证 `OpenAI.Codex` MSIX 包名、Publisher、安装目录、进程与前台窗口，避免把动作发送给伪装窗口
- `SetWinEventHook` 实时监听已验证 Codex 进程的前台、显示、隐藏、焦点、位置和名称事件，进程变化后自动重新绑定
- 主面板可一键暂停或恢复全部 Windows 动作；暂停状态会持久化，动作结果写入不含正文的本机按日审计日志
- Windows 安装版启动后自动检查 GitHub Releases、后台下载更新，并在用户确认后重启安装；portable 版保留为手动更新备用
- 手势必须稳定保持 0.85 秒，松手后才能再次触发

## 摄像头与坐姿辅助

- 4 秒个人坐姿校准、实时评分与骨架叠加
- 本次时长、离席次数与最近坐姿趋势
- 可调灵敏度的坐姿提醒和 30–60 分钟休息提醒
- 摄像头工作区可切换姿态、QR/条码、智能文档扫描、文件 OCR、名片 OCR、人脸隐私、人物背景、物体识别、图片分析与颜色实验室，并支持设备选择、镜像/原图和填满/完整预览
- QR/条码既可从实时摄像头识别，也可在不启动摄像头时导入最大 35 MB 的 PNG、JPEG、WebP 或 BMP 截图/照片；两条路径复用本机 ZXing，结果只在用户复制前留在内存
- 可独立选择并明确开启麦克风；输入电平只在本机内存中计算，不播放、不录制、不上传
- 智能文档扫描支持摄像头、照片或最多 20 页 PDF 导入；PDF 由随包 PDF.js 在本机逐页栅格化，再进入自动/手动四角矫正、透视拉正、左右 90° 旋转、彩色/灰度/黑白增强、多页添加/删除/前后排序、PNG/PDF 导出和扫描页 OCR；OpenCV 在隔离 worker 中离线运行。旋转会同步转换隐私遮盖框，滤镜或边缘重处理后也保留方向；页面排序会连同 OCR 与遮盖状态一起移动，并决定 PDF 导出顺序；每页还会在本机分析原图分辨率、亮度、对比度、清晰度和局部高光，给出非阻断的重拍/复核建议
- 文档模式的 PDF 导入是隐私优先的栅格工作流：原文本层、表单、链接与批注不会保留，导出前必须逐页复核；需要保留原生 PDF 结构时应使用专门 PDF 编辑器
- 扫描页可在导出前绘制、键盘微调、撤销和复核隐私遮盖区；确认后黑色像素永久写入当前 PNG，并由后续 PDF 与 OCR 使用
- 扫描页 OCR 会在本机按文字坐标提示疑似邮箱、电话、中国大陆身份证号和通过校验的金融卡号；建议框必须逐项调整、删除或确认，应用不会自动遮盖内容
- 每张扫描页会按页面保留自己的 OCR 文本与敏感信息建议；文本可人工修正或一键恢复识别原文，复制、票据/MRZ 提取与 TXT 导出使用当前复核文本。切换或排序页面不会丢失结果，旋转、重新拉正、换滤镜或应用遮盖后只清除被改动页的旧结果。可串行识别所有尚未 OCR 的页面，并按当前页序导出合并 TXT；未识别页和人工复核后留空的页面会使用不同占位标记
- 扫描页 OCR 可继续提取中英文票据/发票的商户、日期、单据号、小计、税额、总额和币种；字段必须人工确认后才复制 JSON 或导出 CSV
- 文件 OCR 与扫描页 OCR 可从完整机器可读区提取 ICAO TD1、TD2 和 TD3 证件字段；本机 `mrz` 解析器验证校验位并标记 OCR 易混字符与无效字段，用户必须对照原证件确认后才能复制或导出 JSON。校验位不等同于证件或身份真实性验证
- 文件 OCR 可一次选择最多 20 个 PNG、JPEG、WebP 或 PDF，按顺序在本机处理；同一语言批次复用一个短生命周期 Tesseract worker，批次结束或取消后立即释放，避免每个文件重复加载模型。每个 PDF 最多 20 页，支持逐文件结果、取消、单独 TXT 与合并 TXT 导出，中英文模型和 PDF worker 随应用离线打包
- 图像文件、名片和扫描页 OCR 可打开“置信度复核”，按词框定位低于可调阈值（默认 80，可调 50–95）的疑似难读内容，并显示平均值、最低值与待复核数量；评分只是 Tesseract 的启发式信号，不是正确概率，不会自动改写文字或导出结果。直接读取 PDF 文本层时没有词框，因此不显示该入口
- 图像文件、名片和扫描页 OCR 若包含词框，还可明确导出 schema v1 的版面 JSON 或公式安全的 UTF-8 CSV；输出包含原图文件名/尺寸、从左上角起算的像素坐标、0–1 归一化坐标、行分组与原始置信度。人工修改 OCR 文本或名片字段不会重排识别时的词框；直接读取 PDF 文本层时没有可导出的 Tesseract 版面坐标
- 名片 OCR 会预填姓名、公司、职位、电话、邮箱、网站和地址；用户确认或修正后可导出标准 `.vcf` 联系人文件
- 人脸与照片隐私可在本机自动检测照片中的多张人脸，逐张启用或跳过；漏检时可添加、拖动、键盘移动/缩放或删除手动隐私区，并以模糊、像素化或黑色遮盖永久写入导出 PNG。JPEG/PNG 还会用本机 `exifr` 提示常见 EXIF 拍摄位置、设备、序列号、时间和作者字段。即使没有检测到人脸也可重新编码导出 PNG，原照片中的 EXIF、GPS、XMP、IPTC 与 ICC 数据不会被复制；自动检测与画面内容仍须人工复核
- 人物背景使用随包分发的本机 SelfieSegmenter，把人物与背景分离后可导出透明 PNG、模糊背景或纯色背景；支持人物边界、边缘柔化、原图对照，以及用“保留人物/移除背景”画笔手动修正蒙版，自动分割与画笔结果都必须人工复核
- 物体识别可对用户明确捕获的一帧摄像头画面或导入照片运行随包分发的 EfficientDet-Lite0，定位 80 类常见 COCO 物体；也可临时导入最大 100 MB、带 MediaPipe 物体检测元数据的可信 `.tflite` 模型和可选 UTF-8 标签 TXT。模型先在本机验证且只留内存；两种模型都支持置信度筛选、逐框启用或跳过、结构化 JSON 与永久标注 PNG
- 表情动态面具使用随包分发的 MediaPipe Face Landmarker 在本机跟踪 478 个面部关键点和 52 个 blendshape 表情系数；提供霓虹狐、机甲面罩和庆典假面，分别响应眨眼、抬眉、微笑与张嘴，只有切到“面具”模式时才按需加载模型
- 图片分析可导入两张最大 35 MB 的 PNG、JPEG、WebP 或 BMP，在本机按左上角对齐并用 Pixelmatch 计算感知像素差异；支持键盘可调的前后滑动对照、三档容差、相似度/差异范围指标和差异 PNG 导出。也可一次选择 2–20 张、合计最多 200 MB 的图片，以 128 位双方向 dHash 和 Hamming 距离查找近重复候选，并用 SHA-256 标出字节完全相同的文件；不会自动删除、移动或改写源文件
- 图片分析还提供单图优化：最大 35 MB 的 PNG、JPEG、WebP 或 BMP 可保持宽高比缩到预设最长边，并用浏览器原生 Canvas 转为 PNG、JPEG 或 WebP；JPEG/WebP 品质可调，导出前显示尺寸、体积和增减比例。输出最长边限制为 8192 像素且不超过 2400 万像素；JPEG 将透明像素合成白色，PNG 品质滑杆不生效，浏览器不支持请求格式时会明确失败而不会静默改扩展名。重新编码不复制源 EXIF/GPS，且只有“确认并导出”才写盘
- 图片分析的裁剪旋转工作区支持自由、1:1、4:3、3:4 和 16:9 构图；裁剪框可用鼠标、触控或键盘调整，并显示三分法网格。左右 90° 旋转始终从原图重新生成安全工作栅格，避免累计旋转损失；可预览并导出 PNG/JPEG/WebP。工作图最长边不超过 8192 像素且不超过 2400 万像素，超大原图会明确安全缩放；JPEG 透明区域转白，源文件不会被覆盖
- 图片分析的图片检查工作区可在本机生成 64 档亮度/R/G/B 直方图，并显示尺寸、方向、宽高比、文件大小、平均亮度、亮度标准差、拉普拉斯边缘响应、近黑/近白截断比例以及透明/半透明比例。分析画布最长边 2400 像素且不超过 400 万像素；完全透明像素不计入曝光统计。结果可明确导出 schema v1 JSON，但这些启发值不被描述为审美、对焦、真实性或无障碍结论
- 图片分析的图片标注工作区可在单张本机图片上添加矩形、箭头、编号、文字和局部模糊，支持指针操作、键盘中心添加、列表微调、删除、撤销与重做。最多保留 100 个内存标注；模糊先写入原像素，其他标注随后覆盖。只有生成并复核扁平预览后才导出不含源元数据的新 PNG，源图片和可编辑工程都不会被覆盖或持久化
- 图片分析的联系表工作区可按用户选择顺序编排 2–20 张本机图片，支持 2–5 列、方形/横向/纵向单格、完整显示/居中填满、浅色/深色背景、三档间距和可选序号/文件名。图片可逐项上移、下移或移除；输出自动限制到最长边 8192 像素与 2400 万像素，按顺序逐张解码以控制内存。只有预览并复核后才导出不含源元数据的扁平 PNG，不改写源文件或保存工程
- 图片分析的长图工作区包含拼接与拆分：拼接支持按可见顺序组合 2–12 张图片、纵向/横向、0/8/24 px 间距、白色/深色/透明背景，以及对每张后续图片手动裁去 0%–50% 的顶部或左侧重叠开头；统一到最小交叉轴尺寸以避免放大小图。拆分支持把一张图片纵向或横向连续等分为 2–12 个 PNG，不重复或跳过源像素。解码后超过 8000 万像素的源图会被拒绝；每个结果限制到 8192 像素与 2400 万像素，并须先预览复核再明确导出
- 图片分析的图片调整工作区可对一张本机图片应用曝光、对比度、饱和度、色温和灰度，并提供中性、鲜明、暖调、冷调、黑白与褪色预设。像素始终按曝光→对比度→色温→饱和度→灰度的固定顺序处理；预览限制到最长边 1600 像素及 240 万像素，最终输出限制到最长边 8192 像素及 2400 万像素。前后滑动对照可键盘调整；只有先生成预览并明确确认才导出 PNG/JPEG/WebP。JPEG 透明区域转白，源文件及 EXIF/GPS 不会被覆盖或复制
- 图片分析的批量水印工作区可按可见顺序处理 1–12 张图片，添加 1–80 字符文字或最大 10 MB 的 PNG/JPEG/WebP Logo；支持九宫格位置、全图平铺、10%–100% 不透明度、4%–40% 尺寸、0%–15% 边距和 -45°–45° 旋转。先在首图上滑动复核，再逐张明确导出 PNG/JPEG/WebP；单张 35 MB、合计 160 MB，每个输出限制到 8192 像素与 2400 万像素。源文件和元数据不复制、不覆盖；界面明确提示可见水印可被裁剪或涂抹，不等于内容来源认证
- 图片分析的批处理工作区可按可见顺序处理 1–20 张、单张最大 35 MB 且合计最大 200 MB 的 PNG/JPEG/WebP/BMP；支持六档最长边、PNG/JPEG/WebP、40%–100% 品质、原名加编号或纯编号，以及安全前后缀。首图前后滑动复核后才逐张重新编码并请求下载；输出不放大原图，限制到 8192 边长/2400 万像素，自动去除 EXIF/GPS，并用三位顺序号避免同名覆盖
- 颜色实验室可从最大 35 MB 的 PNG、JPEG、WebP 或 BMP 在本机提取最多 6 个去重后的 OKLCH 代表色；用户可从图片或调色板分别选择文字色与背景色，查看 WCAG 2 AA/AAA 正文和大字对比结果，并复制 CSS 变量或 JSON。对比比率不被描述为整个图片或设计的无障碍结论
- 扫码、扫描页与 OCR 结果只留在内存；只有用户点击保存/导出才写入下载目录
- 统计仅保存在本机 `localStorage`

## Codex 手势

在提醒设置的“手势控制模式”中选择 `Codex` 或 `Windows`；选择会保存在本机。两种模式共用 0.85 秒保持与松手复位机制，但动作映射完全独立。

| 手势 | Codex 动作 | 官方快捷键 |
| --- | --- | --- |
| ✌ 胜利手势 | 打开快速对话 | `Ctrl + Alt + N` |
| ☝ 食指向上 | 激活 Codex 话筒 | `Ctrl + Shift + D` |
| ✋ 张开手掌 | 打开任务选择器 | 本机 App Server |
| 👍 竖起拇指 | 打开代码审查 | `Ctrl + Shift + G` |
| 🤟 I Love You | 切换集成终端 | `Ctrl + 反引号` |
| ✊ 握拳 | 切换任务侧栏 | `Ctrl + B` |

## Windows 手势

| 手势 | Windows 动作 | 固定系统组合键 |
| --- | --- | --- |
| ✌ 胜利手势 | 打开任务视图 | `Win + Tab` |
| ☝ 食指向上 | 提高系统音量 | 音量增大键 |
| ✋ 张开手掌 | 显示桌面 | `Win + D` |
| 👍 竖起拇指 | 打开文件资源管理器 | `Win + E` |
| 🤟 I Love You | 降低系统音量 | 音量减小键 |
| ✊ 握拳 | 静音 / 恢复声音 | 静音键 |

Windows 模式只执行上述固定动作，不接收任意组合键、文字、坐标、命令或脚本。打开文件与任务窗口后，上下文手势仍优先控制该窗口；审批出现时，👍 / ✌ 仍优先用于本次允许 / 拒绝。

文件与任务窗口打开后，手势会进入上下文模式：☝ 选择上一项、✊ 选择下一项、👍 打开或确认、✌ 返回、✋ 从文件进入任务或切换任务分类、🤟 刷新列表。任务操作必须在确认页再次 👍 才会执行；文件打开后会在本机标记为已查看。

当 Codex 发出命令或文件修改审批时，控制面板会切换到审批模式：👍 仅允许本次操作，✌ 拒绝。系统不会通过手势授予整次会话的持续权限。

快捷键桥接只允许固定白名单，并会在发送快捷键前确认前台窗口确实属于 Codex。任务历史通过 Codex App Server 的 `thread/list` 与 `thread/turns/list` 读取；如果接口暂时不可用，可以回退到 Codex 自带的 `Ctrl + G` 历史搜索。

系统明确分为两个完成的 v1 层级：Codex Adapter 自主管理 App Server 生命周期以及任务、事件、审批和程序能力；Windows Control Core 负责 Codex 可信应用身份、实时窗口事件、两套语义动作白名单、急停和审计。Codex 动作要求身份与前台复核；通用 Windows 动作只允许 6 个固定系统组合键。Windows UI Automation 只执行有上限、脱敏的只读结构检查，不点击控件、不读取编辑框或对话正文。完整边界见 [Windows 桌面控制设计](docs/windows-desktop-control.md)。

## 直接运行桌面版

第一次使用请先阅读 [中文使用说明书](docs/user-guide-zh.md)。

```powershell
npm install
npm run desktop
```

开发时使用热更新：

```powershell
npm run dev:desktop
```

点击“开始监测”时 Windows 会请求摄像头权限。只有用户点击“打开麦克风”后应用才会单独请求麦克风权限；关闭后立即停止音频轨道。

## 构建 Windows 安装版与便携版

```powershell
npm run dist:win
```

产物会生成在 `artifacts/`，包括可自动更新的 NSIS `setup.exe`、portable 版、`latest.yml` 和差分更新 blockmap。自动更新只适用于安装版；旧 portable 用户需要先手动下载安装版。本机 `dist:win` 是开发构建，不具备官方签名。

## 发布版本

每次推送 `v*` 标签时，GitHub Actions 会在干净的 Windows 环境中核对标签与包版本、运行测试和 lint，构建并验证已签名的 NSIS 安装版与 portable 版。工作流还会检查 Electron Fuses、ASAR 合规文件、更新元数据、安装/升级/卸载和打包态界面，生成 CycloneDX SBOM、`SHA256SUMS.txt` 与 GitHub 构建来源证明，然后发布不可覆盖的 Release 资产。安装版据此自动发现与下载新版本。发布前可先做无副作用检查：

```powershell
npm run release -- patch --dry-run
```

确认后执行 `npm run release -- patch`（也可用 `minor`、`major` 或明确的 `x.y.z`）。脚本拒绝脏工作区、错误分支、落后远端、重复标签和版本降级，并在修改版本、提交、打标签或推送前要求输入精确确认文本。使用 `--no-push` 可只创建本地提交和标签。

当前已发布的 v0.5.0 安装包尚未配置 Windows Authenticode 证书。更新器会核对 electron-builder 元数据中的 SHA-512，但它不能替代可信发布者签名。新的生产 Release 已配置失败关闭：缺少 `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD`、未设置与证书完全一致的 `WIN_CSC_SUBJECT` 仓库变量，或 setup、portable、安装后主程序、卸载器任一签名无效、发布者不符、缺少可信时间戳时，工作流都会在上传前失败。portable 版不会自动更新。

### Code signing policy

项目正在申请 SignPath Foundation 的开源项目 HSM 托管 Authenticode 签名。批准前不会再发布新的无签名生产版本；批准后只有 GitHub 托管 Release Workflow 产生并经人工批准的项目二进制可以签名。角色、隐私、签名范围和失败关闭规则见 [Code signing policy](docs/code-signing-policy.md)，本机数据与网络边界见 [Privacy Notice](PRIVACY.md)。

已通过的本地证据、GitHub 自动门禁和仍会阻止商业发布的事项见 [Commercial release readiness](docs/commercial-release-readiness.md)。

## 验证

```powershell
npm test
npm run lint
npm run build
npm run desktop:smoke
npm run desktop:smoke:tasks
npm run test:a11y
npm run dist:win
npm run verify:win-artifacts
npm run desktop:smoke:packaged
npm run sbom:generate
npm run readiness:audit
```

桌面冒烟测试会检查打包态页面加载、窗口置顶状态和折叠窗口尺寸；多窗口测试还会确认摄像头区域、6 项手势手册和独立任务选择器同时存在，并验证 Windows 控制暂停后动作被拒绝、恢复后状态正常。结果写入 `work/electron-smoke.json` 与 `work/electron-task-window-smoke.json`。Chromium + axe 端到端门禁覆盖主面板、文件列表、任务筛选、操作选择、确认和 Escape 返回路径，并计算真实颜色对比度。自动测试还覆盖 App Server 运行时发现、任务分页、实时事件、当前任务绑定、活跃回合控制、审批响应、两层状态隔离、桌面动作白名单、实时窗口事件、UI Automation 内容脱敏和 renderer 崩溃限流策略。

`install:smoke` 会真实修改当前用户的安装目录与卸载注册表，因此默认只允许在隔离的 Windows CI 运行；本机必须显式传入 `-AllowLocalMachineChanges`。CI 会下载并同时核对上一公开版本的 GitHub 资产摘要与 `SHA256SUMS.txt`，只有上一版本低于候选版本时才执行 N→N+1 覆盖升级。

`readiness:audit` 是只读的商业发布审计：它只读取 Git/GitHub 配置名称、分支保护、候选版本、工作流结果和本机验证报告，不读取 Secret 值，也不修改远端。结果写入 `work/commercial-release-audit.json`；需要在自动化中遇到 blocker 即失败时，可直接运行脚本并加 `-FailOnBlockers`。

## 隐私与限制

完整隐私说明见 [Privacy Notice](PRIVACY.md)。

- 姿态、手势模型和 WebAssembly 文件都在 `public/`，推理不依赖云端服务。
- 默认不保存图像、视频、OCR 原文件、识别文本或人体关键点；文档、OCR 文本和名片联系人只有在用户明确点击保存/导出后才写入用户下载位置。应用只自动保存按天累计的良好坐姿秒数和有效检测秒数。
- 任务标题、路径和状态只在悬浮面板中临时显示，不写入应用存储。
- Windows 控制审计只记录时间、动作名、目标进程、结果和身份验证状态，不记录任务正文、按键内容、窗口文本或摄像头数据。
- 安装版只向本项目公开的 GitHub Releases 检查更新，不允许界面传入自定义更新地址。
- 普通二维摄像头对遮挡、光线和前后位移较敏感，评分是相对于个人校准姿势的启发式结果。
- 这是健康习惯提醒工具，不提供医疗建议。
